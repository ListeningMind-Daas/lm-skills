# read-search-context — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 무엇이 어떻게 틀렸고 어떻게 고쳤는지, 재발을 막는 검사와 함께 적는다 — 실데이터 실행에서 관측한 수치(검색량 · 건수 · 비율 · 순위)는 적지 않는다.

## v0.3.3 (2026-11-25 · lm-skills 1.9.0 첫 공개)

공개 전 정리: 실데이터 실행 평가에서 관측한 수치 기록을 걷어냈다 — 규칙 · 결함 서술 · 합성 픽스처는 그대로다.

v0.3.x 실행 평가 2건(저장한 경로 · 검색량 · 검색 결과 화면을 다시 쓰고 월별 검색량만 새로 받음) · 2차 블라인드 채점에서 나온 결함:

- **조사 오류** — 사실 ID 뒤 조사가 단위와 맞지 않았다(«…건로»). `assemble`이 단위 받침으로 조사(로/으로 · 은/는 · 을/를 · 와/과 · 가 · 이라/라)를 검사하고 고칠 형태를 알린다
- **창을 옮기면 방향이 바뀌는 전년비를 표시하지 않았다** — 최근 석 달 전년비와 최신 달을 뺀 전년비의 부호가 다른 검색어가 있었다. 미완결 의심 규칙(최신 달 급락)으로는 안 잡힌다 → 표 비고 · 사실 F17 · 안내
- **요청하지 않은 표기 행이 공유 스크립트 결과에 섞였다** — 같은 실행에서 미완결 의심 개수가 스크립트마다 달랐다 → `monthly`가 요청한 검색어 행만 `out/monthly_targets.json`으로 쓰고 두 스크립트는 그 파일을 읽는다
- **미완결 의심이 거꾸로 붙었다**(블라인드 채점 지적) — 공유 규칙(최신 달 급락)에 걸려도 최신 달을 넣은 전년비가 뺀 것보다 높으면 최신 달은 오히려 강하다 → 그 경우는 «미완결 근거가 약하다»로 따로 적고 F15 에서 뺀다
- **묶인 표기가 한 개만 보였다** — 검색량 응답에 온 표기(요청하지 않은 변형)도 `variants`에 적는다
- 리포트 제목을 한국어(«검색 맥락 — 시드») · 월별 차트 계산법에 «한 행 = 4년 월별 값» 설명
- 2차 블라인드 채점: 두 건 모두 스킬 쪽이 더 쓸모 있다고 판정(1차는 두 건 모두 스킬 없는 쪽) — 경로 수 · 줄기 수 · 검색량을 함께 본 판단, 전년 비교, 근거 번호 · 대안 설명
- `collect.py serp`가 원본이 있어 건너뛴 대상을 알린다 · 작성 틀에 선택 키(`headings` · `takeaways`) · 월별 단계가 기본으로 도는 이유 · `metrics_N` 파일 설명

## v0.3.1 — 구글 · 네이버 비중

블라인드 채점에서 스킬 없이 만든 답이 검색 엔진 비중으로 채널을 나눠 실행을 제안했고, 검색어 표에 넣기로 했다.

- `context_nodes.csv`에 `google_avg` · `naver_avg` · `google_share` 열(한국만 · 하한 행 기준 · 응답 `ads_metrics`의 `gg_volume_avg` · `nv_volume_avg` — 추가 호출 0)
- 리포트의 앞뒤 검색 표 · 갈래 표에 구글 비중, 부록 검색어 표에 구글 · 네이버 · 비중 · 검색량 머리는 «구글+네이버»
- 갈래 사실 `B{n}G` · `A{n}G` · 해석 입력에 «결과물을 어디에 둘지 정하는 근거» 안내

## v0.3.0 — 작년 같은 시기와 비교(검색량) 추가

블라인드 채점에서 스킬 없이 만든 답이 «작년 비교는 월별 검색량으로 싸게 답할 수 있다»고 제안했고, 범위에 넣기로 했다.

- 새 단계 STEP 3.5 — 시드 + 뒤 갈래 상위 5 + 앞 갈래 상위 5(기본 최대 11개)의 월별 검색량을 `keyword_info/monthly_volume` 1회로 받는다(1 × 반환 행)
- 시계열 함정 의무가 생겼다(선언 `flags=monthly` · `traps=T1,T2,T3,T4,T5,T6,T7`): 기준월 · 지연(T1) · 마지막 달 미완결(T2) · `volume_trend` 대신 석 달 합 전년비(T3) ·
  기저 게이트(T4) · 결측 월 계산 불가(T6) — 공유 스크립트 `check_refmonth.py` · `trend_yoy.py`(정본 사본)로 처리
- 리포트: 요약 다음 `trend` 섹션(기준월 · 지연 → 전년 · 최근 석 달 · 증감 · 전년비 · 최신 달 제외 전년비 표 → 시드 월별 계열 선 차트) · 질문 Q5 · 데이터 범위의 최신 관측 월 · 비교 기간
- 비교하는 것은 검색량뿐이다 — 지난 시점의 경로(`time_point`)는 계속 견주지 않는다
- 데이터 계약 정본에 `keyword_info/monthly_volume` 조항을 더했다(lm-skills 1.9.0 · 계약 v1.4)

## v0.2.1 — 실행 평가 2건 반영

실제 API 로 돌린 실행 평가 2건에서 나온 결함:

- **단위 중복** — 리포트 문장에 «…개 개»가 나왔다. 사실 ID 가 단위까지 렌더된다는 안내가 해석 입력에 없었고 조립 검사도 잡지 않았다
  → `brief.md`에 안내 · `assemble`이 `{{ID}}` 뒤 단위를 잡으면 멈춘다
- **serp 단가** — 개발 환경에서 계약값(30)보다 낮게 청구됐다. 견적이 높게 잡힌다 → `collect.py serp`가 실측 단가 차이를 경고 · 문서에 명시
- **갈래 검색량에 사실 ID 없음** — 해석 문장에 검색량을 쓸 수 없었다 → `B{n}V` · `A{n}V` 사실 추가
- **해석 입력 표기** — 시드 앞 갈래의 하위 항목이 «다음:»으로 적혔다 → «더 앞:»
- **과한 표현 경고 오탐** — 실행 카드의 내부 지표 이름에 걸렸다 → 내부 지표 칸은 검사에서 뺀다
- **키 · 주소 출처 경고에 기본 선택 없음** → 한 번 묻고 `setup --key-confirmed`로 기록
- **시드 응답의 변형 행**을 경고하지 않았다 → 경고와 치환 규칙 안내
- **S 상한 · 빠듯한 상한의 경로 수가 모호** → S ≤ 18 의 구성을 적고 `quote --budget`이 상한 안 경로 수를 낸다
- 결정식 대조: path_finder 과금이 `50 + 40 × U`와 2건 모두 일치
- 블라인드 채점(같은 원본 응답으로 스킬 없이 만든 답과 비교 · 판정자는 어느 쪽이 스킬인지 모름):
  - 스킬 쪽이 지킨 것 — 절단 표시 · 줄기 수 병기 · 구매 비율 거절(스킬 없는 쪽은 경로 수로 만든 대리 비율 제시) · 근거 번호 · 대안 설명 · 호출 로그
  - 마케터 쓸모 판정은 2건 모두 스킬 없는 쪽(결론 · 갈래 사이 이동 · 검색량으로 갈래 크기 재기 · 엔진 비중 · 작년 비교 조회 제안)
  - 그래서 고친 것 — 갈래 검색량 사실 · 경로 수와 검색량을 함께 보라는 안내 · 조사 오류 · 공백 수(F11)의 뜻 · AI 개요 미확인 표시
  - 열린 결정: «구매 탐색 검색어를 지나는 경로 비중» 같은 대리 지표를 단서와 함께 허용할지 — 지금은 답하지 않는다

## v0.2.0 — 작성 완료

- 주소 · 키를 찾는 순서를 바꿨다: 저장한 값(사용자 설정 폴더)이 먼저, 환경변수는 없을 때만. 첫 모의 실행에서 `setup --base` 로 저장한 주소 대신
  셸의 `LM_API_BASE` 호스트가 쓰였다 — 사용자가 입력한 주소로 키가 가지 않을 수 있었다. 두 주소의 호스트가 다르면 호출 전에 멈추고(종료 코드 5),
  `setup --override-env` 로 사용자가 확인한 환경변수 호스트만 넘긴다. `status` 가 주소 · 키를 읽은 곳과 두 곳의 키가 다른지 보여 준다
- 골격을 채웠다: 수집 층(`collect.py` — 설정 · 견적 · 호출 · 원장 · 예산 가드 · 커넥터 원본 넣기), 집계(`context_paths.py`),
  근거 추출(`serp_evidence.py`), 리포트 조립(`build_report.py`), 경로 맵(`build_map.py`), 고유 자가검증(`selftest_context.py`)
- 온보딩(공급원 · 서버 주소 · 키 · 기본값 · 맥락)과 맥락 견본(`assets/context.starter.json`) · 가이드를 넣었다
- 합성 자료(`assets/fixtures/` — 캠핑의자 · 한국 · 경로 14개)로 문서의 예시 명령이 끝까지 돈다. 실제 조회 결과가 아니다
