# 온보딩 — 처음 한 번 하는 설정

`python3 scripts/collect.py status`가 종료 코드 2로 끝나면 이 순서로 묻고 저장한다. 한 번에 한 가지씩, 모두 합쳐 다섯 번을 넘기지 않는다.
이미 정해진 것(저장한 주소와 키가 있다 · 커넥터만 연결돼 있다)은 묻지 않고 확인만 한다. 환경변수에만 주소가 있으면 그 호스트를 보여 주고 쓸지 묻는다.

## 0. 먼저 살핀다 (묻지 않는다)

| 살핀 결과 | 하는 일 |
|---|---|
| 서버 주소와 키가 모두 있다(`status`가 어디서 읽었는지 보여 준다) | 공급원을 `api`로 두고 2 · 3단계를 건너뛴다. 호스트와 읽은 곳을 보여 주고 맞는지 확인받는다 |
| 저장한 주소와 환경변수 주소의 호스트가 다르다(`status` 종료 코드 3) | 두 호스트를 보여 주고 어느 쪽을 쓸지 묻는다 — 아래 2단계 «주소가 두 곳에 있을 때» |
| ListeningMind 커넥터(`path_finder` · `keyword_info` · `serp` 도구)만 보인다 | 공급원을 `mcp`로 두고 2 · 3단계를 건너뛴다 |
| 둘 다 있다 | 1단계에서 고르게 한다 |
| 둘 다 없다 | 1단계부터 묻는다 |

## 1. 공급원을 고른다

| | `api` | `mcp` |
|---|---|---|
| 누가 부르나 | `collect.py`가 직접 | 에이전트가 커넥터 도구로 부르고 원본을 `collect.py ingest`로 넣는다 |
| 필요한 것 | 서버 주소 · API 키 | 연결된 커넥터 |
| 비용 | 이 스킬의 결정식(검색어 수에 따라) — 호출 전에 견적을 낸다 | 커넥터의 과금 방식을 따른다. 응답에 비용이 없으면 호출마다 사용자가 알려 준 값을 원장에 적는다 |
| 원본 저장 | 자동 | 받은 파일을 요약 · 발췌 없이 넣는다(건수 대조) |

한 실행에서는 공급원을 섞지 않는다. 한쪽이 실패했다고 다른 쪽으로 조용히 넘어가지 않는다 — 같은 자료를 두 번 사게 된다. 멈추고 묻는다.

## 2. 서버 주소를 받는다 (`api`만)

"API 서버 주소를 알려 주세요. 발급 안내나 API 문서에 적힌 주소입니다."

- 스킬에는 주소가 들어 있지 않다. 사용자가 알려 준 값을 그대로 넣는다 — 추측하거나 다른 문서에서 찾아 넣지 않는다.
- `https`로 시작하는 주소만 받는다.
- 저장한 뒤 `collect.py`가 보여 주는 **호스트**를 사용자에게 다시 읽어 주고 맞는지 확인받는다. 키가 그 호스트로 전송된다.

```bash
python3 scripts/collect.py setup --source api --base https://api.example.com --gl kr --lang kr --limit 100 --budget 6000
```

주소는 사용자 설정 폴더(`~/.config/listeningmind/`의 `api-base`)에 저장되고, **저장한 주소가 먼저다**. 환경변수 `LM_API_BASE`는 저장한 주소가 없을 때만 쓴다.

**주소가 두 곳에 있을 때** — 저장한 주소와 환경변수 `LM_API_BASE`의 호스트가 다르면 `collect.py`는 호출하기 전에 멈춘다(종료 코드 5).
셸에 다른 서버용 주소가 남아 있으면 사용자가 입력한 주소 대신 그쪽으로 키가 갈 수 있기 때문이다. 두 호스트를 사용자에게 보여 주고 고르게 한다.

| 사용자의 답 | 명령 |
|---|---|
| 저장한 주소를 쓴다 | `setup --source api --base <저장한 주소> --override-env` — 그 환경변수 호스트를 «쓰지 않음»으로 기록한다. 환경변수 호스트가 바뀌면 다시 멈춘다 |
| 환경변수 주소를 쓴다 | `setup --source api --base <환경변수 주소>` |

## 3. 키를 넣게 한다 (`api`만)

"API 키는 직접 넣어 주세요. 대화에 붙여 넣지 않으셔도 됩니다."

- 사용자가 직접 사용자 설정 폴더에 `api-key`라는 파일로 한 줄 저장하거나(본인만 읽을 수 있게 권한을 둔다), 환경변수 `LM_API_KEY`로 넣는다.
  찾는 순서는 주소와 같다 — 사용자 설정 폴더가 먼저, 환경변수는 없을 때만.
- 두 곳에 다른 키가 있으면 `status`가 알리고 사용자 설정 폴더의 키를 쓴다. 주소와 키를 서로 다른 곳에서 읽었으면 그 키가 이 호스트용인지 확인받는다.
- **에이전트는 키를 받아 적지 않는다.** 대화에 키가 올라왔다면 파일에 옮기지 말고, 다시 발급받을지 사용자에게 알린다.
- 키는 화면 · 호출 원장 · 원본 응답 파일 · 리포트 어디에도 쓰이지 않는다. `collect.py status`는 «있음 / 없음»만 보여 준다.
- 키가 없으면 발급처에 문의하도록 안내하고 분석을 시작하지 않는다.

확인은 `python3 scripts/collect.py status`로 한다(호출 없음 · 크레딧 0). 실제 연결 확인은 첫 실행의 시드 확인(1크레딧)이 겸한다.

## 4. 기본값을 정한다

| 항목 | 물을 말 | 기본 |
|---|---|---|
| 국가 | "주로 보는 국가는 어디인가요? (kr · us · jp)" | 없음 — 요청마다 다르면 비워 두고 실행할 때 묻는다 |
| 리포트 언어 | 국가와 다르면 따로 묻는다 | 국가와 같게 |
| 경로 수 | "경로는 몇 개 받을까요? 50 · 100 · 150" — 견적을 함께 보여 준다 | 100 |
| 크레딧 상한 | "분석 한 건에 크레딧을 얼마까지 써도 되나요?" | 없음 — 반드시 받는다 |

견적은 `python3 scripts/collect.py quote --limit 100 --serp 18`로 낸다. 견적은 계획값이지 상한이 아니라고 말한다.

## 5. 맥락 파일 (선택)

"우리 브랜드와 경쟁 브랜드를 표시해 볼 수 있습니다. 지금 채울까요, 나중에 할까요?"

- 지금: `assets/context.starter.json`을 `assets/context.json`으로 복사하고 `references/context-guide.md`대로 채운다.
- 나중에: 그대로 진행한다. 스킬은 범용으로 돌고, 리포트 데이터 범위에 «회사 맥락 미설정»이 적힌다.
- 회사 맥락을 채운 스킬 폴더는 공개 저장소에 되돌려 올리지 않는다.

## 설정이 저장되는 곳

| 무엇 | 어디 |
|---|---|
| 공급원 · 기본값 | 작업 공간의 `work/read-search-context/settings.json` |
| 서버 주소 | 사용자 설정 폴더의 `api-base`(먼저) → 없으면 환경변수 `LM_API_BASE` |
| 키 | 사용자 설정 폴더의 `api-key`(먼저) → 없으면 환경변수 `LM_API_KEY` |
| 맥락 | 스킬 폴더의 `assets/context.json` |

스킬 폴더 안에는 주소와 키를 두지 않는다 — 폴더를 다른 사람에게 넘길 때 따라가지 않게 한다.
설정을 바꾸려면 `setup`을 다시 돌린다. 실행 한 건만 다르게 하려면 `init`의 `--gl` · `--limit` · `--budget`으로 준다.

## 주소와 키를 서로 다른 곳에서 읽었을 때

`status`가 «주소는 사용자 설정 폴더, 키는 환경변수에서 읽었다»고 경고하면 한 번 묻는다: "이 키가 <호스트>용 키가 맞나요?"

| 사용자의 답 | 하는 일 |
|---|---|
| 맞다 | `setup --source api --base <저장한 주소> --key-confirmed`(환경변수 주소와 다르면 `--override-env`도) — 다음부터 경고하지 않는다 |
| 아니다 · 모른다 | 그 호스트용 키를 사용자 설정 폴더의 `api-key`에 넣게 하고 기다린다. 호출하지 않는다 |
