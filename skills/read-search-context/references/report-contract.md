# 리포트 렌더링 계약 (정본)

version: 1.2

> 이 파일은 **정본**이다. 리포트를 내는 LM 스킬은 자기 폴더 `references/`에 사본을 두고 따른다.
> 고칠 때는 정본을 고치고 사본을 다시 배포한다 — `shared/verify_shared.py`가 드리프트를 검사한다.

## 0. 무엇이 공통이고 무엇이 스킬의 몫인가

| 공통 (이 계약 · 렌더러가 강제) | 스킬의 몫 |
|---|---|
| 문서 뼈대 순서 · 첫 화면 경계 · 데이터 범위 필드 | 각 섹션에 무엇을 넣을지 · 어떤 질문에 답할지 |
| 지표 표현 규칙(절대량과 증감률 병기 · 결측 · 기간 정렬) | 어떤 지표 · 어떤 차트를 쓸지 |
| 차트 메타데이터 · 발견 카드 · 실행 카드의 필드 | 카드의 내용 · 문장 |
| 금지 표현 · 숫자 추적(문구 숫자는 사실 목록에서) | 사실 목록을 만드는 계산(스킬 스크립트) |
| 호출 순서 · 호출 로그 · 비용 보고서의 형식 | 호출 원장을 남기는 수집 스크립트 |
| 테마 · 목차 · 반응형 · 인쇄 · 접근성 | — |

데이터 계약(`lm-data-contract.md`)은 **숫자가 맞는가**를, 이 계약은 **그 숫자를 판단할 수 있게 보여주는가**를 다룬다.
렌더러 `scripts/render_report.py`가 아래 규칙 중 기계로 판정할 수 있는 것을 오류로 막는다(§7).

## 1. 문서 뼈대 — 순서 고정

| 순서 | `kind` | 담는 것 | 필수 |
|---|---|---|---|
| 1 | `summary` | 핵심 발견 · 지지 근거 · **반대 근거** · 가능한 결정 | 예 |
| 2 | `scope` | 데이터 범위 표(§2) — 렌더러가 `scope` 입력으로 채운다 | 예 (자동) |
| 3 | `trend` | 절대 규모 → 최근 변화 → 과거 방향 → 반복 계절성, 이 순서로 | 시계열을 쓰면 |
| 4 | `structure` | 관심 구조 — 고민 · 제품 · 성분 · 선택 질문 등 하위 묶음의 차이 | 선택 |
| 5 | `action` | 기회와 실행 — 근거 → 해석 → 실행 가설 → 검증 조건. 콘텐츠 초안 · 랜딩 구성은 여기 또는 부록 | 선택 |
| 6 | `appendix` | 전체 수치 · 계산 정의 · 출처 · 원고 + 렌더러가 붙이는 사실 목록 · 호출 순서 · 호출 로그 · 비용 보고서(§9) | 예 |

- 섹션은 이 순서로만 놓는다. 같은 `kind`를 여러 섹션으로 나눌 수는 있다(연속 배치).
- 콘텐츠 초안 · 카피 · 랜딩 구성은 **분석 본문(trend · structure)보다 앞에 두지 않는다.**

## 2. 첫 화면 경계와 데이터 범위

- `boundary`(필수) — 첫 화면 맨 위에 한 문장. **무엇을 관측했고 무엇을 아직 관측하지 못했는지.**
  예: "과거 가을 패턴과 최근 여름 변화이며 올해 가을은 미관측". 기준월이 끝나지 않은 시즌을 다루면 반드시 쓴다.
- `lede_html`(필수) — 짧은 요약. 본문 서술은 `sections`에 쓴다.
- `scope`(필수 필드): `collected_at`(수집일) · `latest_month`(최신 관측 월) · `gl`(국가) · `selection`(검색어 선정 방법)
  · `missing`(누락) · `excluded`(제외와 사유) · `windows`(기준 기간 · 비교 기간).

## 3. 지표 표현

1. **증감률만 쓰지 않는다.** 증감률을 보이는 표는 기준 기간 값 · 비교 기간 값 · 절대 증감을 함께 보인다
   (표 열 `role`: `base` · `compare` · `abs_change` · `pct_change`). 기준값이 작아 증가율이 커진 행은 `note`로 설명한다.
2. **기간을 통일한다.** 모든 비교는 `scope.latest_month`로 끝나는 같은 창을 쓴다. 불완전한 기간(끝나지 않은 달 · 연도)의 합계 비교는 하지 않는다.
3. **결측은 0이 아니다.** 결측 값은 `null`로 넘기고 화면에는 `—`로 보인다. 0으로 바꾸지 않는다.
4. **최근 변화와 장기 방향을 나눈다.** 단일 전년비로 "지속 성장"을 판정하지 않는다 — 여러 해의 같은 기간 값을 함께 둔다.
5. **정규화에는 원수치를 붙인다.** 계절 지수 · 정규화 추이는 같은 기간의 절대 검색량 표(차트 `raw`)를 함께 낸다.
   연도별 값을 같이 보여 반복성과 편차를 확인하게 한다.
6. **다른 모집단은 합산하지 않는다.** 서로 다른 검색어 묶음(예: 성분 vs 제품)을 비교할 때는 그 사실을 `limits`에 적고, 증감률과 절대 변화량을 병기한다.
7. **표본으로 시장을 말하지 않는다.** 검색어 표본으로 시장 전체 규모 · 고민 비중 · 구매 요인 순위를 만들지 않는다.
   임의 성장 등급과 근거 없는 통계적 유의성을 표시하지 않는다.
8. **순위 문장은 기준을 밝히고, 방향어는 값을 따른다.** "가장 크게 줄었다"처럼 기준이 둘일 수 있는 문장은 증감률인지 절대 증감인지 쓴다 — 둘의 1위가 다르면 둘 다 적는다. "오르던" · "줄었다" 같은 방향어는 문장에 들어가는 값의 부호·배수(1 미만이면 오른 것이 아니다)와 맞춘다. 헤딩·문장을 템플릿으로 만들면 이 둘을 값에서 고른다.

## 4. 차트

- 모든 차트에 메타 7종 필수: `title`(제목) · `takeaway`(핵심 해석 한 문장) · `period`(기간) · `unit`(단위) · `method`(계산법) · `source`(출처) · `limits`(한계).
- 차트는 **저장된 계산 결과**로 그린다. 값은 입력 JSON에 있고, 렌더러는 값을 만들지 않는다. 축 눈금 같은 표시용 숫자는 검증 대상이 아니다.
- **색만으로 판단을 전달하지 않는다** — 값 · 이름 라벨을 함께 그린다.
- 유형별 규칙
  - `line` — 비교하는 계열은 같은 기간 · 같은 축. 크기 차이로 작은 계열이 가려지면 `normalized: true` 보기와 원수치 표(`raw`)를 함께 낸다.
  - `bar` — 증감률 막대에는 절대 변화량(`abs`)을 병기한다.
  - `heatmap` — 정규화 지수 + 같은 칸의 절대 검색량(`raw`) 필수. 행 = 연도 또는 항목, 열 = 월.
  - `scatter` — 축 이름을 정확히(예: "과거 계절성 × 최근 여름 전년비"). **점 면적은 값에 비례**(반지름 ∝ √값), 크기 범례 필수.

## 5. 발견 카드와 실행 카드

**발견 카드** (`finding`): `id` · `evidence`(사실 ID 목록) · `observed`(관측 사실) · `interpretation`(파생 해석)
· `alternatives`(대안 설명) · `limits`(판단 한계) · `actions`(연결된 실행 카드 ID).

**실행 카드** (`action`): `id` · `evidence` · `hypothesis`(검증할 가설) · `deliverable`(결과물) · `owner_role`(담당 역할)
· `internal_data`(필요한 내부 데이터) · `criteria.expand` · `criteria.revise` · `criteria.stop`(확대 · 수정 · 중단 조건).

발견마다 원자료와 계산을 따라갈 수 있고, 실행마다 근거와 검증 조건이 있어야 한다.

## 6. 숫자 추적 — 사실 목록

- 문구에 들어가는 수치는 `facts`에 등록하고 `{{F1}}`처럼 부른다. 사실마다 `value` · `unit` · `label`(4-Label) · `source` · `calc`.
- 문단 · 헤딩 · 차트와 표의 메타 · 카드의 모든 글 칸에 사실 목록을 거치지 않은 수치(콤마 · 소수 · % · 100 이상 · 배 · 건)를 직접 쓰면 렌더러가 멈춘다.
  연도(2025년) · 월(9월) · 열두 이하의 작은 정수 · 단위 글자 뒤에 글자가 이어지는 말(«배수» · «건강»)은 허용한다.
- 사실의 `source`에 호출 ID(`C3`)를 쓰면 부록의 호출 로그로 이어진다. 없는 호출 ID는 렌더러가 막는다.
- 검사를 통과하려고 임의 숫자를 `facts`에 추가하지 않는다 — 사실은 스킬 스크립트의 저장 계산 결과에서 만든다.

## 7. 렌더러가 막는 것 · 사람이 보는 것

| 렌더러가 오류로 막는다 (exit 1) | 사람이 본다 |
|---|---|
| 뼈대 순서 위반 · 필수 섹션 누락 · `boundary` · `lede_html` · `scope` 필드 누락 | 반대 근거 · 대안 설명이 실질적인가 |
| 차트 메타 7종 누락 · heatmap `raw` 누락 · scatter 크기 범례 누락 | 헤딩이 결론을 말하는가 |
| `pct_change` 열만 있고 `base` · `compare` · `abs_change` 열이 없는 표 | 표본으로 시장을 일반화하지 않았는가 |
| 카드 필수 필드 누락 · 없는 사실 ID · 없는 실행 카드 참조 | 금지 표현이 문맥상 쓰였는가(경고) |
| 사실 목록을 거치지 않은 문구 숫자 · 미치환 `{{…}}` · 출력의 `None` · `NaN` · `undefined` | 화면 폭 · 테마 · 키보드 · 인쇄 확인 |
| 호출 기록 없음 · 호출 필드 누락 · 호출 ID 중복 · 음수 비용 · 없는 호출을 출처로 쓴 사실 | 헤딩 · 반대 근거가 데이터와 모순되지 않는가 — 순위의 기준(증감률·절대)과 방향어가 값과 맞는가(§3-8) |
| 문단 HTML 안의 블록 태그(`<p>` 중첩 등) | |

## 8. 화면과 인쇄

- 문장은 읽기 좋은 폭(약 72자), 표 · 차트는 넓게. 좁은 화면에서 표 · 차트는 글자를 줄이지 않고 내부 가로 스크롤.
- 밝은 · 어두운 테마, 목차, 키보드로 목차 · 접기 영역 이동, 포커스 표시.
- 인쇄: 접힌 영역을 펼치고, 표 머리를 페이지마다 반복하고, 차트 · 카드가 페이지 경계에서 잘리지 않게 한다. 부록도 인쇄된다.

## 9. 호출 순서 · 호출 로그 · 비용 보고서 — 산출물마다

같은 산출물의 숫자가 **어떤 호출에서, 어떤 순서로, 얼마를 들여** 나왔는지 산출물마다 따로 볼 수 있어야 한다.

- 입력 `provenance.calls`(필수): 호출마다 `id` · `tool` · `params`(호출 조건) · `cost` · `raw`(원본 응답 파일) · `status`,
  권장 `step`(단계) · `at`(시각) · `purpose`(목적) · `returned`(반환 수) · `data_through`(데이터 마지막 달).
  저장본만 썼으면 그 저장본을 만든 호출을 `cost: 0` · `reused_from`으로 적는다 — 호출 기록이 비는 산출물은 없다.
- 선택 `provenance.estimate`(견적) · `monthly_used`(월간 누적 — 잔여량이 아니다).
- 이 기록은 **수집 스크립트의 원장**(원본 응답 · `cost_detail.total_cost`)에서 만든다. 손으로 적지 않는다.
- 렌더러가 부록에 세 뷰를 붙인다: **호출 순서**(번호 · 단계 · 도구 · 목적 → 반환 · 비용) · **호출 로그**(호출별 표) ·
  **비용 보고서**(이번 산출물 소진 = 호출 비용 합 · 재사용 · 견적 대비 · 월간 누적 · 도구별 · 단계별). 목차에서 각각 바로 간다.
- 렌더러가 HTML 옆에 `<이름>.calls.csv`(호출 로그)와 `<이름>.cost.json`(비용 보고서)을 따로 쓴다 — 표 계산기 · 다른 시스템에서 연다.
