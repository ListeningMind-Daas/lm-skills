# map-entry-situations — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 무엇이 어떻게 틀렸고 어떻게 고쳤는지, 재발을 막는 검사와 함께 적는다 — 실데이터 실행에서 관측한 수치(검색량 · 건수 · 비율 · 순위)는 적지 않는다.

## v0.1.2 (2026-11-23 · lm-skills 1.8.0)

- 계약 v1.3 사본 — `ads_info` 금지를 풀었다. 시계열만 필요하면 `ads_info`를 쓸 수 있고, 단가는 첫 호출 `cost_detail`로 확인한다(명세 1/키워드 · 운영 환경에서도 1로 확인).
- SKILL.md의 «`ads_info`는 쓰지 않는다» 문장을 새 규칙으로 바꿨다 — 분석 절차·산출 컬럼은 바뀌지 않았다.
- 공개 전 정리: 실데이터 실행에서 관측한 수치 기록(검색량 · 건수 · 비율 · 순위 · 실행 날짜)을 걷어냈다 — 규칙 · 결함 서술 · 합성 픽스처는 그대로다.

## v0.1.1 — P0 두 건 수정 (앱 캐시 재생 비교에서 발견)

근거: 앱 «CEP Finder»의 가전 카테고리 KR 실행 캐시 응답을 스킬에 재생한 비교(새 API 호출 0 · 크레딧 0).
실행 A = 배포 사전 + 카테고리 브랜드 목록, 실행 B = 카테고리별로 다시 쓴 사전(채점 기준 라벨).

- **P0-1 사전 패턴이 공백을 지운 canonical 아무 데서나 걸려 낱말 경계를 넘었다.** `직수정수기`에 `수정`, `얼음정수기미니` ·
  `정수기미세플라스틱`에 `기미`, `정수 영어로`에 `수영`, `미세플라스틱`에 `스틱`, `아이콘 정수기`(제품명)에 `아이`가 걸렸다.
  배포 사전 그대로(A)에서는 제품 유형 검색(`직수정수기` 류)이 오탐 CEP «문제:땀·피지·지속»으로 모여 상위에 올랐고 아무 경고도 없었다.
  카테고리 결속 검색어 기준 사전 정밀도가 매우 낮았다.
  - 수정: `cep_lib.Lexicon.match` — 원문(공백 유지)에서 어절 시작 위치를 기억하고, 카테고리어(키워드 · `anchor_terms`)와 브랜드명을
    «□»로 가린 뒤, 패턴은 **어절 시작 · 가린 자리 앞뒤에서 시작하는 일치만** 인정한다(끝은 열림 — 조사 · 어미 · 합성어 허용).
    패턴에 적힌 카테고리어 · 브랜드명도 같은 «□»로 바꾼다(`간이정수기` 패턴이 계속 걸린다). 같은 canonical의 표기는 그룹 대표의 분류를 따른다
    (이중 집계 방지). `situation_pool` · `cep_map`(경로 포함)은 canonical 대신 원문 검색어로 분류한다
  - 정밀도 신호: 검색어 `match_term` · `match_scope`(어절 / 어절 일부), CEP `partial_token_share`, 머리 `partial_token_share_lo` —
    `cep_summary.md` 표 · 리포트 «반대 근거»에 실린다
  - 배포 사전: 충돌하기 쉬운 패턴을 조였다 — `아이` → `아이(?:들|용|…)?(?![가-힣a-z])|우리아이`, `수정` → `수정화장`,
    `스키(?!니…)`, `젤(?!리)`, `봄(?!버)`, `유아(?!인)`. 제품 크기 · 형태(`미니` · `소형` · `접이식`)는 상황이 아니라 «비상황:제품 속성»으로 옮겼다
    (A에서 «목표:가볍게·휴대» 오탐은 주로 `미니 …` 제품 검색이었다). `포장이사` · `반포장이사`를 이사 테마에 넣었다(어절 시작 규칙으로 잃는 합성어)
  - 재실행(A, 같은 채점): 결속 정밀도가 크게 오르고 재현율은 그대로, 거짓 1위 «땀·피지·지속»이 사라졌다. 미분류는 조금 늘었다
    (오탐이 미분류로 돌아와 사전 빈칸이 보인다)
  - 재발 검사: `selftest_cep.py` `lexicon_boundary_tests`(위 실패 문자열 8개가 v0.1.0 패턴에 걸리던 것을 확인한 뒤 v0.1.1에서 안 걸리는지 ·
    참 사례 `이사 정수기` · `아기 분유 정수기` · `사무실 정수기` · 다른 낱말 앞머리 반례 `COLLISION_WORDS`) + `rank_window_tests`의 지도 수준 검사
- **P0-2 순위가 스킬 스스로 «미완결 의심»이라 한 마지막 달을 포함했다(계약 T2).** 추세 창은 마지막 달을 뺐지만 순위 · 게이트는
  `volume_total`(기준월 포함 12개월)이었다. 기준월 한 달에 검색량이 몰린 검색어 하나가 B판의 한 CEP를
  상위권으로 올렸다. 같은 실행에서 `check_refmonth`가 그 달을 미완결 의심으로 표시했다.
  - 수정: 순위 · 순위 게이트를 **추세와 같은 창**(기본: 기준월 한 달 전에서 끝나는 12개월)의 대표 시계열 월 합으로 매긴다(`rank_window` ·
    `window_volume_lo` · `window_nonbrand_lo/_hi`). 시계열 없는 그룹만 `volume_total`로 대신하고 비중을 `window_series_share`에 적는다.
    마지막 달 포함 순위는 옆 열 `priority_rank_incl_last`, 다르면 `rank_shift_incl_last` · 머리 `rank_shifts_incl_last`
  - 재실행(B 사전): 그 CEP가 상위권에서 내려가고, 마지막 달을 넣으면 순위가 달라지는 CEP들이 옆 열로 드러났다
  - 재발 검사: `rank_window_tests` — 기준월 한 달만 20,000으로 뛴 `사무실 정수기`가 순위 1위가 되지 않는지(창 21,600 → 2위, 포함 시 1위 → `1→2`)
- 리포트: 1순위 카드 · CEP 지도 표 · 산점도 면적이 순위 창 논브랜드 값을 쓰고, 표에 «마지막 달 포함 순위» 열을 넣었다. `assets/report.example.json` 재생성
- 남긴 것(P1 · 다음 판): 결속 검색량만 순위(P1-1) · path 효용 게이트(P1-2) · 폭증 시계열의 계절 오독(P1-3) · 카테고리 밖 브랜드의 결속 판정(P1-4) ·
  브랜드 미지정 시 «미점유» 문구(P1-5). 어절 시작 규칙은 붙여 쓴 합성어 뒷말(`코크살균`의 `살균`)을 놓친다 — 필요하면 사전에 합성어를 적는다

## v0.1.0 — 작성 완료 (실행 평가 전)

- 서버 앱 «CEP Finder»의 아이디어를 공개 키트 규칙으로 옮겼다. 바뀐 점과 이유:
  - **CEP 합성을 LLM에서 규칙 사전으로** — `assets/themes.json`(6축: 계기 · 시점 · 장소 · 사람 · 문제 · 목표 + 비상황 + «미분류» 버킷).
    같은 데이터에서 같은 지도가 나와야 비교 · 재실행이 된다. 에이전트가 쓴 CEP 이름 · 해석은 `[추정]`
  - **뜻 고정(S0)을 LLM 호출에서 사용자 확인 파일로** — `sense.json`(`confirmed_by_user`가 true가 아니면 스크립트가 멈춘다)
  - **`keyword_info` `ads_info` 호출을 2단 조회로** — 전량 `ads_metrics` 1 → `select_stage2.py` 규칙으로 고른 대표만 `all` 10.
    `ads_info`는 단가가 환경마다 달라(10 · 1) 쓰지 않는다
  - **`volume_trend` 가중 추세를 버리고** `monthly_volume` 전년 동기(12 · 3개월)를 직접 계산
  - **가중 합성 우선순위 점수(0.40 · 0.35 · 0.25)를 버리고** 논브랜드 하한 단일 순위 + 옆 열(추세 · 계절 · 브랜드 연결)
  - `cluster_finder` · `serp` 제외(비용), `path_finder`는 trace-search-journey의 파일럿 → 예산 게이트 방식(`path_gate.py`)
- 함정 T1~T8 처리 — 마지막 달 기본 제외 · 결측 월 검색어는 시계열 모집단에서 제외 · CEP 순위 게이트 · 표기변형 하한/상한 ·
  호출 단위 절단 · 논브랜드 순위
- 검증: `selftest_cep.py`(합성 픽스처 — 역위상 계절 · 브랜드 지배 CEP · 결측 월 · 시드 표기 변경 · 같은 검색 중복) 통과.
  **실제 크레딧 실행 평가는 아직이다** — evals 2케이스 이상을 돌리기 전까지 «검증 완료»가 아니다
