# benchmark-competitors — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 무엇이 어떻게 틀렸고 어떻게 고쳤는지, 재발을 막는 검사와 함께 적는다 — 실데이터 실행에서 관측한 수치(검색량 · 건수 · 비율 · 순위)는 적지 않는다.

## v1.3.3 (2026-11-23 · lm-skills 1.8.0)

- 계약 v1.3 사본 — `ads_info` 금지를 풀었다. 시계열만 필요하면 `ads_info`를 쓸 수 있고, 단가는 첫 호출 `cost_detail`로 확인한다(명세 1/키워드 · 운영 환경에서도 1로 확인).
- 공개 전 정리: 실데이터 실행에서 관측한 수치 기록(검색량 · 건수 · 비율 · 순위 · 실행 날짜)을 걷어냈다 — 규칙 · 결함 서술 · 합성 픽스처는 그대로다.

## v1.3.2 (2026-10-13 · lm-skills 1.7.0)

공유 스크립트 사본 갱신 — 분석 절차·산출 컬럼은 바뀌지 않았다.

- 계약 v1.2 사본 — T4 기저 게이트를 묶음·그룹 순위 문장에도 적용 · T6 여러 창(연도)을 나란히 비교하는 합계는 모든 창에 값이 있는 검색어로 모집단 고정(실습 리허설 실행 평가에서 나온 결함).
- `selftest.py` — SKILL.md가 비었거나 골격 자리표시자(⬜로 표시된 미작성 칸 등)가 남아 있으면 실패한다. 이전에는 스크립트만 돌려 빈 SKILL.md에서도 «통과»를 냈다(워크숍 사전 실행, lm-skill-creator 0.2.4)
- `build_universe.py`·`check_refmonth.py`·`series_dedup.py`·`trend_yoy.py`·`selftest.py` — Windows cp949 콘솔에서 `—`·`⚠` 출력 시 UnicodeEncodeError로 죽던 것을 막는다(표준 출력을 UTF-8로). 이전 판은 cp949 콘솔 모사에서 출력 중 죽었다(`trend_yoy.py --help`·`check_refmonth.py` 실행 등)

## v1.3.1 (2026-09-30 · lm-skills 1.6.2)

공유 스크립트 결함 수정 — 선크림(KR) 예시 실행에서 보고된 것. 저장된 분석 폴더로 0크레딧 재현 후 고쳤다.

- `build_universe.py` — keyword_info 응답 안에서 같은 keyword·같은 내용의 행이 두 번 오면 두 행 모두 대표(`dup_of` 빈칸)가 되어 그룹 상한(합)에 이중으로 들어갔다. 완전히 같은 행은 하나로 합치고 «완전 중복 행 N행 합침»을 출력한다. 이 결함은 그룹 상한만 부풀리고 하한은 건드리지 않는다.
- `trend_yoy.py` — «게이트 미만·계산 불가·같은 검색 중복 N행 제외» 한 줄을 사유별 세 수(계산 불가 · 같은 검색의 중복 · 게이트 미만)로 나눴다(benchmark-competitors 실행에서 세 사유가 한 수로 섞여 보고됐다). `--ref-month`가 비교 창의 끝 달이며 본문 분석 창에 맞출 때 준다는 것을 도움말에 적었다. 같은 keyword의 완전 중복 행도 합친다.
- `series_dedup.py` — `collapse_identical`(같은 keyword의 완전 중복 행 합치기 · 내용이 다르면 첫 행만 쓰고 경고)을 추가했다. `build_universe`·`coverage_curve`·`trend_yoy`가 먼저 이것을 거친다.
- `selftest.py` — 위 결함 여섯 가지의 회귀 검사를 추가했다(고치기 전 스크립트에서는 전부 실패함을 확인).
- 계약 v1.1 — keyword_info 1회 1,000키워드 상한과 나눠 호출한 응답의 병합법(`data`·`request_detail`·`cost_detail`·`used_credits`)을 적고, T5에 완전 중복 행 합치기(⓪)를 넣었다.
- `themes-schema.md` — 변형치환이 «공백 제거 다음에» 적용된다고 적혀 있었으나 구현(`series_dedup.canon`)은 공백을 남긴 채 먼저 치환한다. 코드 기준으로 고치고 «치환 순서» 절을 추가했다.

## v1.3.0 (2026-09-30 · lm-skills 1.6.1)

선크림(KR) 예시 실행에서 보고된 결함을 저장 응답으로 0크레딧 재현한 뒤 고쳤다.

| 결함 | 조치 | 근거 (저장 응답 재계산) |
|---|---|---|
| P0 구글 지표 공유 묶음이 네이버 볼륨이 다른 쌍까지 «같은 검색»으로 보고 대표 1행만 2단·하한에 넣음 | `bench_common.components` ④ **네이버 분리 변형**: 구글 공유로만 이어졌고 네이버 볼륨이 대표와 다른 행은 네이버 볼륨을 하한에 더한다. `plan_queries stage2`가 이 행을 2단에 따로 넣고(네이버 12개월 ≥ `--min-volume`) ✓/✗ 목록·빠진 네이버 볼륨을 출력. `brand_benchmark`는 2단에 있으면 월 패널에 그 달 `nv`를 더하고, 없으면 gap_alert에 과소집계 경고. `dup_basis=네이버 분리(…)` · `series_basis=대표 행 + 네이버 분리 변형(하한 기준)` | «헤라 선크림»이 «헤라 썬크림»과 구글 지표 공유로 묶여 네이버 볼륨이 하한에서 빠짐 → 고친 뒤 헤라 12개월 하한 = 상한, 하한·상한 순위 뒤집힘이 모든 브랜드에서 사라짐. 논브랜드 «썬크림» 묶음도 하한 = 상한. 월 패널의 점유율·전년 동기 값이 함께 바뀌고, 네이버 분리 변형이 2단 대상에 더해져 크레딧이 늘었다 |
| P2 `combos`가 브랜드명 단독·브랜드 × 범용 수식어를 항상 넣고, 속성어를 뒤에 붙여 드문 어순(«선크림 톤업»)을 만듦 | `--no-brand-alone` · `--no-brand-modifiers` 옵션, 설정 키 `probe_prefix_modifiers`(앞에 붙는 속성어 — «톤업 선크림» · «헤라 톤업 선크림»). 출력에 조합 구성·안내 | 선크림 실행은 exclude 정규식으로 우회했다 |
| P2 `_비교(복수 브랜드)` 버킷 0에 «별칭 확인» 경고 — combos는 비교 검색어를 만들지 않으므로 기본이 0 | 비교 버킷은 «요청하지 않았으면 정상» 문구로 바꾸고 «별칭 확인»은 브랜드 버킷에만 | 선크림 실행의 stage2 출력 |
| P2 STEP 6 `trend_yoy.py` 명령에 `--ref-month`가 없어 최신 월(미완결)을 기준으로 잡음 | 명령에 `--ref-month 2026-07`(분석 월) 추가·설명 | 선크림 실행은 `--ref-month 2026-07`을 따로 붙여 다시 돌렸다 |

회귀: `selftest_benchmark.py` 5절(네이버 분리 변형 2단 포함·하한·월 패널). 기존 P1-2 기대값 조정 — «나이키도스»(네이버 120)는 구글 공유가 아니라 네이버 분리로 분류되고 하한에 120이 더해진다.
