# discover-sub-markets — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 «무엇이 몇 % 틀렸다»처럼 근거 수치와 함께 적는다.

공유 스크립트 사본 갱신 — 분석 절차·산출 컬럼은 바뀌지 않았다.

- 계약 v1.2 사본 — T4 기저 게이트를 묶음·그룹 순위 문장에도 적용 · T6 여러 창(연도)을 나란히 비교하는 합계는 모든 창에 값이 있는 검색어로 모집단 고정(2026-10-13 실습 리허설 실행 평가에서 나온 결함).
- `selftest.py` — SKILL.md가 비었거나 골격 자리표시자(⬜로 표시된 미작성 칸 등)가 남아 있으면 실패한다. 이전에는 스크립트만 돌려 빈 SKILL.md에서도 «통과»를 냈다(2026-10-12 워크숍 사전 실행, lm-skill-creator 0.2.4)
- `build_universe.py`·`check_refmonth.py`·`series_dedup.py`·`trend_yoy.py`·`selftest.py` — Windows cp949 콘솔에서 `—`·`⚠` 출력 시 UnicodeEncodeError로 죽던 것을 막는다(표준 출력을 UTF-8로). 이전 판은 cp949 콘솔 모사에서 출력 중 죽었다(`trend_yoy.py --help`·`check_refmonth.py` 실행 등)

## v1.3.0 (2026-09-30 · lm-skills 1.7.0)

2026-09-30 선크림(kr · limit 90 · 상한 5,500) 실행에서 나온 결함 4건을 고쳤다. 저장본으로 재현·대조했다(0크레딧).

- **시드 대조 불일치(P1)**: API가 시드 `선크림`을 그래프에 `썬크림`으로만 돌려줬다. `nodes`는 공백·대소문자만 비교해
  «시드가 그래프에 없다 — score는 판정하지 않는다»를 냈는데, `score`는 universe canonical(변형치환 `썬→선`)로 대응해
  정상 판정했다(시드 노드 1개). 두 명령이 같은 대조 함수(원 표기 → 공백·대소문자 → 변형치환 규칙)를 쓰게 했고,
  어느 단계에서 걸렸는지 같은 문구로 출력한다. `nodes`·`score`에 `--rules themes.json`을 추가했다. 규칙이 아직 없는 STEP 2에서는
  경고와 함께 한 글자 차이 후보(`썬크림`)를 `[추정]`으로 보여 준다. 저장본 재실행: `nodes --rules`가 «변형치환 규칙으로 «썬크림»에 대응»,
  `score` 산출 `submarkets.csv`·`stage2_keywords.json`은 이전과 바이트 단위로 같다.
- **시드 추세 병합 절차 없음(P2)**: STEP 1이 시드 `monthly_volume`을 `trend_yoy.py`에 «함께 넣으라»고 했지만 그 스크립트는 파일 하나만 받는다.
  실행에서는 손으로 `all_plus_seed.json`(2단 6행 + 시드 2행 = 8행)을 만들었다. `submarkets.py merge-all`(키워드당 한 행 · 기준월 불일치·값 불일치 경고)을
  추가하고 STEP 6 명령에 넣었다. 저장본 재실행: 같은 순서(all → seed_all)로 합치면 `trend.csv`가 실행 결과와 바이트 단위로 같다.
- **파일럿 예산 절차 없음(P1)**: 상한 5,500에서 보수 상한(`N ≤ 2 × limit`)으로는 limit 52가 한계라 절단이 거의 확실했다. 실행에서는
  `cluster_finder/keyword_list`(30 + 2 × N) 파일럿으로 limit 90 → 89개(208크레딧)를 먼저 쟀고, 본 호출 `cost_detail` 4,600(= 150 + 50 × 89)으로
  일치했다. 파일럿 노드 집합과 본 호출 노드 집합도 89개 전부 같았다. `budget --pilot-nodes N --cap 상한`(정확한 금액 · 남는 S · 초과면 종료 코드 1)과
  `nodes --pilot`(노드 집합 대조)을 추가하고, 커넥터 표·예산식·STEP 2에 파일럿을 넣었다. «파일럿 N = 본 호출 N»은 1건 관측이라 `[가정]`으로 둔다.
  관측 상한 근거를 4건 → 5건(limit 90 → 89 추가)으로 갱신했다.
- **종료 코드 유실(P2)**: 실행이 `score … | tee`로 출력을 저장해 종료 코드(0/2/3)를 잃었다. STEP 5에 종료 코드 표와 `set -o pipefail`·리다이렉트 예시를 넣었다.
- `selftest_submarkets.py`에 위 4건 회귀 검사를 추가했다(시드 표기변형 대조의 nodes·score 일치 · 파일럿 금액 208/4,600/4,907 · 상한 초과 종료 코드 1 ·
  merge-all 키워드당 한 행 · SKILL.md의 pipefail 안내).

## v1.2.2 (2026-09-30 · lm-skills 1.6.2)

공유 스크립트 결함 수정 — 2026-09-30 선크림(KR) 예시 실행에서 보고된 것. 저장된 분석 폴더로 0크레딧 재현 후 고쳤다.

- `build_universe.py` — keyword_info 응답 안에서 같은 keyword·같은 내용의 행이 두 번 오면 두 행 모두 대표(`dup_of` 빈칸)가 되어 그룹 상한(합)에 이중으로 들어갔다. 완전히 같은 행은 하나로 합치고 «완전 중복 행 N행 합침»을 출력한다. 실측(2026-09-30 선크림 KR, separate-buyers 1/2 호출 742요청·767행 중 25행): 그룹 상한 21,338,741 → 18,075,746(−15.3%), 하한 16,102,051은 그대로.
- `trend_yoy.py` — «게이트 미만·계산 불가·같은 검색 중복 N행 제외» 한 줄을 사유별 세 수(계산 불가 · 같은 검색의 중복 · 게이트 미만)로 나눴다(benchmark-competitors 실측: 제외 33행 = 계산 불가 1 + 게이트 미만 32). `--ref-month`가 비교 창의 끝 달이며 본문 분석 창에 맞출 때 준다는 것을 도움말에 적었다. 같은 keyword의 완전 중복 행도 합친다.
- `series_dedup.py` — `collapse_identical`(같은 keyword의 완전 중복 행 합치기 · 내용이 다르면 첫 행만 쓰고 경고)을 추가했다. `build_universe`·`coverage_curve`·`trend_yoy`가 먼저 이것을 거친다.
- `selftest.py` — 위 결함 여섯 가지의 회귀 검사를 추가했다(고치기 전 스크립트에서는 전부 실패함을 확인).
- 계약 v1.1 — keyword_info 1회 1,000키워드 상한과 나눠 호출한 응답의 병합법(`data`·`request_detail`·`cost_detail`·`used_credits`)을 적고, T5에 완전 중복 행 합치기(⓪)를 넣었다.
