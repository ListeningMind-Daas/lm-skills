# forecast-season-demand — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 무엇이 어떻게 틀렸고 어떻게 고쳤는지, 재발을 막는 검사와 함께 적는다 — 실데이터 실행에서 관측한 수치(검색량 · 건수 · 비율 · 순위)는 적지 않는다.

## v0.1.1 (2026-11-23 · lm-skills 1.8.0)

- 계약 v1.3 사본 — `ads_info` 금지를 풀었다. 시계열만 필요하면 `ads_info`를 쓸 수 있고, 단가는 첫 호출 `cost_detail`로 확인한다(명세 1/키워드 · 운영 환경에서도 1로 확인).
- SKILL.md의 «`ads_info`는 쓰지 않는다» 문장을 새 규칙으로 바꿨다 — 분석 절차·산출 컬럼은 바뀌지 않았다.
- 공개 전 정리: 실데이터 실행에서 관측한 수치 기록(검색량 · 건수 · 비율 · 순위 · 실행 날짜)을 걷어냈다 — 규칙 · 결함 서술 · 합성 픽스처는 그대로다.

## v0.1.0 (2026-11-19 · 작성 완료 — 실행 평가 전)

기존 수요 예측 웹 앱의 잡(시드 → 연관 검색어 → 세그먼트 → 3·6개월 예측 · 시즌 일정)을 키트 스킬로 옮겼다.
앱의 모델 선택(여러 예측 모델을 백테스트로 고름) · LLM 단계(관련성 필터 · 세그먼트 · 요약)는 옮기지 않고 결정적 규칙으로 바꿨다.

| 앱 | 이 스킬 | 이유 |
|---|---|---|
| 모델 6종 중 백테스트로 선택 · 체제 분류 | 전년 같은 달 × 최근 W개월 전년비(r) 하나 + 범위 + 1회 점검 | 같은 입력 → 같은 숫자. 어떤 규칙이 숫자를 냈는지 문서 한 줄로 설명된다 |
| LLM 관련성 필터 | themes.json `exclude.pattern`(사람이 확인한 정규식) | 다시 돌려도 같은 풀 |
| LLM 세그먼트 | themes.json `themes`(배열 순서 첫 매칭) | 세그먼트 경계를 사전으로 남겨 재현 |
| LLM 요약 | `build_report.py` 틀 문장 + `[추정]` · 숫자는 `{{ID}}`만 | 숫자 추적(렌더링 계약 §6) |
| `ads_info` 전량 시계열 | `ads_metrics` 스크린 → 통과분만 `all`(2단 조회) | 계약 §1 — `ads_info` 단가가 환경마다 다름 |
