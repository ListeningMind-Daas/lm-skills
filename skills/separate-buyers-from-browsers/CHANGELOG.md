# separate-buyers-from-browsers — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 «무엇이 몇 % 틀렸다»처럼 근거 수치와 함께 적는다.

## v1.3.0 (2026-09-30 · lm-skills 1.6.1)

2026-09-30 선크림(KR) 예시 실행에서 보고된 문서 불일치를 고쳤다. 저장 응답으로 0크레딧 재집계해 확인했다.

| 결함 | 조치 | 근거 |
|---|---|---|
| 판매 채널명(px)이 브랜드 사전에 들어가는 것을 막는 규칙·경고 없음 | STEP 2 «판매 채널명은 brands에 넣지 않는다». `buyer_share.py`가 브랜드 사전 이름이 거래 티어(채널·가격) 마커에도 걸리면 stderr 경고 + 리포트 머리 «⚠ 브랜드 사전에 거래 마커…» | 저장 응답 재실행: `px(채널 지명)` 경고 · 산출 CSV는 이전과 동일. 민감도: px를 채널로 옮기면 논브랜드 안 거래 의도 하한 기준 10.5% → 11.8%(브랜드 18개 보강 사전 기준) |
| 1,000개 초과 분할 안내 없음 | STEP 1 «1,000개를 넘으면 나눠 부른다» — 합칠 때 `data`·`request_detail.keywords`·`cost_detail` 병합 또는 요청 배열을 `--requested`에 | 선크림 1,484개를 742 + 742로 나눠 불렀다 |
| «LM이 거래로 읽는 미분류 헤드 = 거래 마커 누락 후보» 서술이 브랜드 누락과 구분 안 됨 | STEP 5에 사례(1건 관찰)와 가르는 순서(브랜드 → 거래 마커 → 헤드는 고치지 않음) | «샤넬 선크림»: 사전에 샤넬이 없어 미분류 헤드 · LM «거래» |
| `build_universe`와 `buyer_share`의 브랜드 매칭 방식 차이 미기재 | STEP 2에 명시(부분일치 vs ASCII 토큰 단위) · 판정은 `buyer_share.py` 것만 쓴다 | — |

회귀: `selftest_buyers.py` `check_channel_brand`.
