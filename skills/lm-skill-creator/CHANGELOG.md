# lm-skill-creator — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 «무엇이 몇 % 틀렸다»처럼 근거 수치와 함께 적는다.

## v0.2.3 (2026-09-30 · lm-skills 1.6.2)

공유 스크립트 결함 수정 — 2026-09-30 선크림(KR) 예시 실행에서 보고된 것. 저장된 분석 폴더로 0크레딧 재현 후 고쳤다.

- `themes-schema.md` — 변형치환이 «공백 제거 다음에» 적용된다고 적혀 있었으나 구현(`series_dedup.canon`)은 공백을 남긴 채 먼저 치환한다. 코드 기준으로 고치고 «치환 순서» 절을 추가했다.

## v0.2.2 (2026-09-30)

2026-09-30 크리에이터로 `track-sunscreen-ingredients`를 만든 실행에서 감사기가 뚫린 것이 드러났다 — 완성본의 표 칸 12곳을
⬜로 되돌려도 P0 0으로 통과했다.

- `audit_skill.py` 미작성 검사: 줄 맨 앞의 미작성 기호만 세던 것을 위치와 무관하게 기호마다 센다. 골격의 미작성 기호 19개 중 3개만 잡던 것이
  19개 전부를 잡는다. P0 설명에 위치(파일:줄)를 붙인다. `evals.json`에 남은 미작성 기호는 P1(«eval 케이스 미작성»)
- 4-Label 검사: 라벨 이름만 세던 것을 «적용이 적힌 줄»이 있어야 세도록 — 칸이 빈 4-Label 표가 통과하지 않는다
- 함정 검사: 공유 문서 사본(`themes-schema.md` 등)과 미작성 줄을 본문에서 뺀다 — 빈 골격에서 T1·T4(골격 안내문)·
  T5·T8(themes-schema.md 사본)이 충족되던 것을 막는다. 빈 골격 기준 함정 미처리 4건 → 8건
- `selftest.py`: «공유 자산 없음» 시험이 저장소 `shared/scripts`를 지웠다 복원하던 것을 임시 사본 + `new_skill.py --shared`로
  바꿨다(중간에 끊겨도 정본 무손상). 위 세 가지 우회를 막는지 검사하는 항목을 더했다 — 이전 감사기로 돌리면 3건 실패
- `new_skill.py`: 출력의 로컬 절대경로를 현재 폴더 기준 경로로. 숨은 옵션 `--shared`(시험용 정본 위치)
- SKILL.md STEP 4: 감사기가 무엇을 빼고 보는지, 저장소 밖에서 만든 스킬의 사본 검사 방법

13개 공개 스킬 감사 결과는 바뀌지 않았다(전부 P0 0 · P1 0 · P2 0).

## v0.2.1 (2026-09-29 · lm-skills 1.6.0)

- 변경 이력을 SKILL.md 에서 이 파일로 옮기고, 판 번호를 frontmatter `metadata.version` 으로 옮겼다. 분석 절차·산출물은 바뀌지 않았다.
- `new_skill.py` 골격이 SKILL.md 대신 `CHANGELOG.md` 를 만들고 판 번호를 `metadata.version` 에 쓴다. 머리 버전 메모도 넣지 않는다. STEP 6·7 문구를 이 방식에 맞췄다.
- 본문 속 판 이력 서술을 걷어냈다 — 규칙의 근거 수치는 본문에 남기고, 이력 문장은 아래 «본문에서 옮긴 기록»으로 옮겼다.

## 이전 기록

### v0.1 → v0.2 (2026-09-07)

크리에이터로 `map-your-market`을 재생성시킨 검증에서 나왔다. 재생성본은 함정 8종을 모두
재현하고 첫 감사에서 P0 0으로 통과했지만, **그 과정에서 크리에이터의 결함이 드러났다.**

| # | 결함 | 조치 |
|---|---|---|
| ① | **크리에이터가 자기완결적이 아니었다** — 재사용 스크립트를 특정 태스크 스킬에서 복사했고, 그 폴더가 없으면 **조용히 아무것도 복사하지 않은 채** "배치돼 있다"고 말했다 | 정본을 `shared/scripts/`로 승격. 없으면 **생성 중단**. 사본은 출처 표식으로 식별해 해시 검사 |
| ② | **`themes.json` 스키마가 어디에도 없었다** — 스크립트 둘이 요구하는데 알려면 소스를 읽어야 했다. `theme_primary`가 배열 순서로 정해진다는 것도 미문서 | `references/themes-schema.md` 신설 + `shared/assets/themes.template.json` 배포 |
| ③ | **의무 판정이 문구 추론이었다** — `기회`·`진입` 같은 흔한 단어로 T8이 강제되고, "이 커넥터는 쓰지 마라"는 문장이 커넥터 사용으로 잡혔다 | 골격이 **의무 선언 블록**을 심고 감사기가 그것을 기준으로 검사. 선언 없는 레거시는 추론 + P2 |

> ④~⑧(컬럼 검사 오탐 · 경로 예시 불일치 · 완료 게이트의 크레딧 의존)은 ①②③과 함께
> 부분 반영했다 — 경로를 저장소 루트 기준으로 통일했고, 골격에 "표만 채우면 걸린다"는 힌트를
> 넣었고, 완료를 «작성 완료»와 «검증 완료»로 분리했다. 컬럼 검사 오탐은 미해결로 남는다.
