# lm-skill-creator — 변경 이력

판 번호의 정본은 SKILL.md frontmatter `metadata.version` 이다. 새 판을 낼 때 두 곳을 같이 고친다.
결함은 무엇이 어떻게 틀렸고 어떻게 고쳤는지, 재발을 막는 검사와 함께 적는다 — 실데이터 실행에서 관측한 수치(검색량 · 건수 · 비율 · 순위)는 적지 않는다.

## v0.4.1 (2026-11-23 · lm-skills 1.8.0)

- `audit_skill.py` — `ads_info` P1 규칙: «쓰지 않는다»를 요구하던 것을 «단가를 `cost_detail`로 확인한다는 근거가 있으면 통과»로 바꿨다(계약 v1.3).
- 공개 전 정리: 실데이터 실행에서 관측한 수치 기록(검색량 · 건수 · 비율 · 순위 · 실행 날짜)을 걷어냈다 — 규칙 · 결함 서술 · 합성 픽스처는 그대로다.

## v0.4.0 (2026-10-13 · lm-skills 1.7.0)

«우리 회사 스킬»의 맥락을 파일로 남기게 했다. 실습 2(스킬 만들기)에서 질문 · 브랜드 · 경쟁사 · 용어를 브라우저 입력 칸으로 받아
프롬프트에만 넣었더니, 대화가 끝나면 스킬은 다음 요청에서 우리 회사를 몰랐다(에이전트는 스킬 폴더 밖을 읽지 않는다).

- 공유 자산 추가: `shared/references/context-schema.md`(맥락 파일 스키마 v1.0) · `shared/assets/context.template.json` ·
  `validation-table.template.json`. 회사마다 다른 것은 `assets/` 맥락 파일 셋(context · validation-table · themes)에만 두고,
  요청마다 다른 것은 `work/<스킬>/<실행 ID>/request.json` 실행 기록으로 남긴다
- `new_skill.py --context`: 맥락 파일 견본 · 스키마 사본 · 분류 사전 견본을 배치하고 SKILL.md 에 «우리 맥락» 섹션(STEP 0)과 `flags=context` 를 심는다
- `audit_skill.py`: `flags=context` 면 맥락 파일 · 검증표가 없거나 ⬜가 남으면 P0, 질문 ID 비었거나 겹치면 P0,
  완료 기준 · 관측 · 가설 빈 질문 P1, `themes.json` 없음 P1, STEP 0 절차 없음 P1(골격 안내문은 세지 않는다),
  내부 지표에 값으로 보이는 숫자(콤마 · 소수 · 세 자리 이상 · % 원 억 만 건) P1 — «3개월 재구매율» 같은 이름은 통과
- 공유 `selftest.py`: 맥락 파일이 있으면 스키마 필수 키 · 검증표 질문 ID 를 본다(스킬 사본 10개 동기화)
- 키트 `.gitignore` 에 `work/` — 실행 결과 · 회사 맥락 작업본을 커밋하지 않는다
- 만드는 곳(키트)과 돌리는 곳(키 · API 연결이 있는 작업 공간)을 나눠 적었다 — `work/`는 에이전트를 연 작업 공간 기준, API 호출은 설치된 작업 공간의 연결 · 키(스킬 안에 두지 않음)
- `new_skill.py`: 리포트 견본 배치 메시지가 `report.sample.json` 을 두 번 찍던 것 수정

공개 스킬 12종 감사 결과 불변(P0 0 · P1 0 · P2 0) · selftest 12종 통과.

> ④~⑧(컬럼 검사 오탐 · 경로 예시 불일치 · 완료 게이트의 크레딧 의존)은 ①②③과 함께
> 부분 반영했다 — 경로를 저장소 루트 기준으로 통일했고, 골격에 "표만 채우면 걸린다"는 힌트를
> 넣었고, 완료를 «작성 완료»와 «검증 완료»로 분리했다. 컬럼 검사 오탐은 미해결로 남는다.
