# 감사 루브릭 — P0/P1/P2 분류 기준

## 원칙: 고객이 막히는가, 조용히 틀리는가

| 등급 | 정의 | 판단 기준 |
|---|---|---|
| **P0** | 출시 차단 | 고객이 **막히거나**, 막히지 않고 **틀린 산출물을 완성**한다 |
| **P1** | 신뢰 저하 | 배포는 가능하나 문의·오해를 부른다 |
| **P2** | 위생 | 내용이 아니라 «공개물로서» 문제 |

**둘 중 더 위험한 것은 후자다.** 산출물이 정상적으로 완성되고, 숫자도 그럴듯하고,
틀렸다는 신호가 어디에도 뜨지 않는다. 리뷰로 안 잡히므로 검사 수단으로 막아야 한다.

## 감사기가 못 잡는 것

`audit_skill.py`는 **문서에 처리가 적혀 있는지**만 본다. 적힌 처리가 옳은지, 실제로 도는지는
못 본다. 그래서 세 겹으로 본다:

1. **정적 감사** — 계약 준수 여부 (`audit_skill.py`)
2. **자가검증** — 문서 예시가 실제로 도는가 (`selftest.py`)
3. **실행 평가** — 실제 카테고리에서 무엇이 나오는가 (eval 런)

세 번 다 통과해도 결함이 나온다. v1.1·v1.2·v1.3 모두 «통과한 실행»에서 새 결함이 나왔다.
그러니 첫 실사용 몇 건은 사람이 산출물을 본다.
