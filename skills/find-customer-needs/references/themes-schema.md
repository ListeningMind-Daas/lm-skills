# `themes.json` 스키마

`build_universe.py`와 `coverage_curve.py`가 함께 읽는다. 분류(테마·브랜드)와 표기변형
정규화가 이 파일 하나에 묶여 있다. **카테고리마다 새로 쓴다** — 예시를 그대로 쓰면 안 된다.

정본 템플릿: `shared/assets/themes.template.json` (골격 생성 시 `assets/`로 복사된다)

## 구조

```json
{
  "rules": { "변형치환": { "썬": "선" } },
  "themes": [ { "name": "제형", "pattern": "선스틱|스틱|쿠션|젤" } ],
  "brands": ["라운드랩", "조선미녀"],
  "no_match": { "with_brand": "브랜드·제품명", "without_brand": "코어·일반" }
}
```

| 키 | 필수 | 뜻 |
|---|---|---|
| `rules.변형치환` | 권장 | `canonical` 그룹키를 만들 때의 치환 쌍. NFKC 정규화 → 소문자화 → 공백 제거 **다음에** 적용된다. 같은 수요가 두 표기로 갈리는 쌍만 넣는다 |
| `themes[].name` | ✅ | 테마 이름 |
| `themes[].pattern` | ✅ | 정규식. **canonical 문자열**(공백 없음·소문자·치환 적용됨)에 대해 평가된다 — 원문에 맞추면 안 걸린다 |
| `brands` | ✅ | 브랜드·제품 라인명 목록 |
| `no_match.with_brand` | ✅ | 테마는 안 걸렸는데 브랜드가 걸린 경우의 라벨 |
| `no_match.without_brand` | ✅ | 둘 다 안 걸린 경우의 라벨 |

## 두 가지 함정

**① `theme_primary`는 배열 순서로 정해진다** — 최적 매칭이 아니다. 여러 테마에 걸리면
**먼저 선언된** 테마가 주 테마가 되고, 걸린 것 전부는 `facets` 컬럼에 남는다.
분석 목적에 따라 순서를 바꾼다 — 진입 검토면 대상·상황 축을 위로 올린다.

**② `brands`가 비면 T8(논브랜드 분리)이 무력화된다.** 빠진 브랜드는 전부 논브랜드로 집계되어
**신규 진입 여지를 과대평가**한다. 실측에서 브랜드 사전을 54개로 줄였더니 논브랜드 비중이
40.3% → 55.1%로 뛰었다. 기억으로 쓰지 말고 **수집된 상위 볼륨 키워드에서 뽑아** 채운다.

## 채우는 순서

1. 골격 생성 시 배포된 `assets/themes.template.json`을 `themes.json`으로 복사
2. `rules.변형치환` — 해당 언어권의 표기 흔들림
3. `themes` — 축을 먼저 정하고 순서를 정한 뒤 패턴을 쓴다
4. **`brands`는 1차 확장 결과를 보고 채운다** — 시작 시점에는 알 수 없다
5. 유니버스 조립 후 논브랜드 비중을 보고 사전 누락을 역추적
